# ASR source conversion: LiteRT and ExecuTorch

Research snapshot: 2026-10-21. Documentation/source inspection only; no weights downloaded, conversion performed, build run, or device inference measured. “Published” below means that the file is present in the publisher's listing, not that Lacan has verified its bytes or accuracy. Mutable `main` source links are discovery evidence, not reproducible build pins; resolve their full commits and dependency locks before an experiment.

## Decision

Use **LiteRT as the first common Android GPU → supported-NPU qualification path**, but distinguish two experiments. For the shortest path to a real accelerator artifact, start with the published **Parakeet TDT v3 5-second FP32 LiteRT encoder**, keeping its TDT orchestration/decoder on CPU initially. It has a source conversion recipe, Android pipeline, GPU support claims, and chip-specific NPU files to inspect. It avoids making the success of runtime evaluation depend on inventing a GigaAM exporter. For a controlled conversion of Lacan's already-tested Russian model, **GigaAM v3 e2e CTC FP32 remains the simpler graph and best second candidate**: one encoder/head invocation and CPU CTC collapse, with no token-by-token neural decoder. This ordering is an engineering inference from available artifacts and graph structure, not a measured performance ranking.

ExecuTorch deserves an equal bounded **Parakeet Vulkan comparison**, because it now has an actual model-specific exporter and Android runner path. It is not merely a hypothetical PyTorch alternative. Do not begin by converting full Whisper large-v3: its memory and repeated decoder calls add risk before the runtime question is settled. Neither ecosystem establishes Exynos 1580 NPU support by providing generic export APIs. See the device/runtime limits in [android-acceleration.md](../android-acceleration.md).

## Existing Lacan contract

The current `SherpaEngine.kt` sends normalized float PCM at 16 kHz to sherpa's GigaAM-aware 64-bin frontend, uses a single NeMo CTC graph and greedy decode, and explicitly selects CPU. `SherpaWhisperEngine.kt` loads separate INT8 encoder/decoder ONNX files, selects transcription rather than translation, requests fresh language detection for each call when language is auto, and divides oversized inputs into 25-second windows. `SherpaTransducerEngine.kt` loads Parakeet encoder/decoder/joiner, uses 128 features from the catalog and CPU greedy decode; it has no forced-language control. All three have synchronous sherpa decode: cancellation drops results rather than aborting an in-flight native call.

The catalog's existing ONNX downloads are approximately GigaAM 886 MB FP32 / 320 MB INT8; Whisper medium 946 MB / full large-v3 1,776 MB INT8; Parakeet 670 MB INT8. Their immutable revisions and file hashes are in [model-options.md](../model-options.md) and `ModelCatalog.kt`. An exported `.tflite` or `.pte` requires a separate engine, graph contract and model identity. ONNX dynamic quantization is not an interchangeable accelerator quantization format.

Published LiteRT Whisper files are produced by the **LiteRT-LM-Unity project**, not original OpenAI exports. Their cards identify TensorFlow Transformers `TFWhisperForConditionalGeneration` → two signatures → `ai-edge-quantizer 0.8.0`. They use INT8 weights with FP32 activations; INT4 variants use mixed recipes. Listed bytes are roughly **832 MB / 664 MB** for medium INT8/INT4 and **1.63 GB / 1.15 GB** for large-v3. Cards use different rounded units; use actual file metadata for download budgets. Both decoders rerun the fixed token sequence without KV cache. Publisher validation is nine Korean/English clips with CPU results; it does not validate Russian, mixed speech, or accelerated execution. [Medium card](https://huggingface.co/litert-community/whisper-medium), [medium files](https://huggingface.co/litert-community/whisper-medium/tree/5d9d61399ce05d80fdfab6eb458a10ba78021b91), [large-v3 card](https://huggingface.co/litert-community/whisper-large-v3), [large-v3 files](https://huggingface.co/litert-community/whisper-large-v3/tree/4182353a0c7607c3e1084ea29446e362a3000ae2).

The Parakeet LiteRT listing contains `parakeet_tdt_0.6b_v3_5s_f32.tflite` (~2.42 GB), `..._5s_i8.tflite` (~614 MB), stateful variants, and FP32 AOT files named for Qualcomm/MediaTek/Google chips. Presence of an AOT file proves an uploaded compilation artifact, not successful inference on every named device. The card's bundled metadata describes 16 kHz audio, a 128-bin Slaney log-mel frontend and an 8,192-token SentencePiece vocabulary. Its published CPU/English observations must not be presented as Lacan/A56 or Russian measurements. [Publisher card](https://huggingface.co/litert-community/parakeet-tdt-0.6b-v3), [file inventory](https://huggingface.co/litert-community/parakeet-tdt-0.6b-v3/tree/main).

Google's ASR sample explicitly distinguishes TDT NPU support on Pixel 10 from CTC support on Galaxy S23/24. Those are **different Parakeet models**: the CTC sample cannot establish multilingual TDT v3 compatibility. Its source includes conversion, verification, NPU compilation, frontend and host decoding components. [ASR sample](https://github.com/google-ai-edge/litert-samples/tree/main/samples/litert/speech_recognition), [supported model registry](https://github.com/google-ai-edge/litert-samples/blob/main/samples/litert/speech_recognition/convert/supported_models.py).

## Export paths and architecture

**GigaAM:** load the source `v3_e2e_ctc` configuration/checkpoint, wrap encoder plus CTC head with fixed feature shape and valid-length input, and try LiteRT Torch conversion. The official ONNX source already isolates `forward_for_export(features, feature_lengths)` → head scores plus encoded lengths; it does not export raw-waveform preprocessing into that graph. Preserve the exact e2e head/tokenizer, rather than substituting plain `v3_ctc` and losing punctuation/normalization. ExecuTorch's alternative is capture through `torch.export`, backend partitioning and serialization to `.pte`; it has no model-specific success evidence here. [Official model/export source](https://github.com/salute-developers/GigaAM/blob/main/gigaam/model.py), [official model families](https://github.com/salute-developers/GigaAM).

**LiteRT source path:** `litert_torch.convert(...)` / named signatures → `.tflite` → CompiledModel. The converter advertises broad CPU coverage and initial GPU/NPU coverage; PyTorch capture success does not imply GPU-compatible operators. Google's ASR converter uses fixed sample inputs, separate encode/decode signatures and optional one-token decode signature. Its DRQ recipe has INT8 channelwise weights and FP32 activations. This is source reauthoring, not renaming Lacan's ONNX. [LiteRT Torch](https://github.com/google-ai-edge/litert-torch), [ASR conversion script](https://github.com/google-ai-edge/litert-samples/blob/main/samples/litert/speech_recognition/convert/convert_to_tflite.py).

**Whisper:** keep acoustic encoding on GPU/NPU as the first split; run language-token handling, greedy selection/termination and, initially, decoder on CPU. Compare against a coherent full converted CPU pipeline before mixing runtime outputs with existing sherpa. A later cached decoder needs explicit token-position, attention-mask and KV-cache contracts. The official ExecuTorch runner expects encoder and text-decoder methods, tokenizer assets and a separate audio preprocessor; its Android demo currently warns that `AsrModule` is not released and needs an AAR with audio JNI. Source examples establish a path, not a drop-in Maven replacement. [Runner/export instructions](https://github.com/pytorch/executorch/blob/main/examples/models/whisper/README.md), [Android integration caveat](https://github.com/meta-pytorch/executorch-examples/blob/main/whisper/android/WhisperApp/README.md).

**Parakeet TDT:** encode once, then retain LSTM hidden/cell state and run prediction/joint steps under a CPU host loop that selects both token and duration. A token can advance zero frames; preserve the upstream guard against unbounded symbols at a frame. This is not CTC collapse and not Whisper's autoregressive attention decoder. The LiteRT wrapper rewrites masked convolution/normalization for GPU capture and calls its fixed-window encoder with `length=None`; therefore padding parity is a release gate. ExecuTorch source exports projected encoder features and separate decoder-step/joint methods. Start with CPU decoding to bound dispatch/transfer cost. [LiteRT TDT wrapper](https://github.com/google-ai-edge/litert-samples/blob/main/samples/litert/speech_recognition/convert/parakeet_tdt.py), [ExecuTorch TDT source](https://github.com/pytorch/executorch/blob/main/examples/models/parakeet/export_parakeet_tdt.py).

ExecuTorch's Parakeet README documents Vulkan `8da4w` and optional FP16 internal computation, while preprocessing stays portable. These are new quantization/computation choices, not reuse of sherpa INT8 weights. The exact exporter/torch/torchao/runtime commits must be frozen together. [Exporter options and Vulkan runner](https://github.com/pytorch/executorch/blob/main/examples/models/parakeet/README.md).

## Frontend, window and text gates

All routes require identical 16 kHz mono PCM scaling, resampling, FFT window/hop, centering/padding, mel filter convention, log floor and feature normalization. Compare feature tensors before model logits. GigaAM source uses natural-log clamped mel power with model-config parameters; do not replace it with Whisper frontend just because both are log-mel. [GigaAM preprocessing](https://github.com/salute-developers/GigaAM/blob/main/gigaam/preprocess.py).

Whisper uses 400-point FFT, 160-sample hop, 30-second/3,000-frame input and its particular log10 dynamic-range normalization. Medium uses 80 mel bins; large-v3 uses 128. Tokenizer IDs, language/task/no-timestamp tokens and vocab must come from the exact model; a shared generic token table is insufficient. Punctuation is model output, not evidence of a separate punctuator. [OpenAI frontend](https://github.com/openai/whisper/blob/main/whisper/audio.py), [large-v3 configuration](https://huggingface.co/openai/whisper-large-v3/blob/main/config.json).

Fixed-window offline models do not become native streaming models after conversion. Choose one window size per artifact; pad the final window using the reference frontend and retain true lengths/masks where the graph supports them. Verify that padding cannot affect valid attention/convolution results, and crop decoded CTC frames using encoded lengths. Test speech cut at window boundaries, short speech followed by silence, and overlap seam duplicates. Google's sample uses overlapping windows and zero-padding, explicitly calls these offline models, and merges overlap output; it is a useful pattern, not proof its policy matches Lacan's VAD/finalization contract. [Sample windowing and decoding](https://github.com/google-ai-edge/litert-samples/blob/main/samples/litert/speech_recognition/README.md).

## Bounded experiments and conversion gates

1. **Freeze provenance first:** full source/model commits, tokenizer/config hashes, converter/quantizer/runtime versions, output signature/types and license manifest. For published files, obtain full revision and SHA-256 before catalog admission; this research did not hash weights. Do not silently substitute turbo, CTC-only Parakeet or non-e2e GigaAM.
2. **One CPU conversion gate:** one fixed window, one model, batch one. Compare eager source, converted CPU and current sherpa on the same short public/consented Russian, English/mixed, silence and boundary fixtures. Save frontend error, logits/token agreement, decoded text and punctuation separately. Define numeric tolerances before export; exact token parity is preferred for FP32, and every difference needs transcription review.
3. **One GPU gate:** on A56, inspect delegate partitions and actual execution, then one cold and a few warm bounded calls. Include frontend, upload/download, CPU decoder and merge time. Stop on wrong text, unsupported lowering, OOM or unstable driver. Record peak PSS/native/GPU memory, initialization/finalization time and cancellation behavior; do not infer memory from file size.
4. **Quantization gate only after FP32 parity:** create a new recipe from source rather than converting already-quantized ONNX. For static activation INT8, calibrate on representative Russian/mixed speech, noise, silence, quiet/loud audio and padded tails, with a held-out set. Measure WER/CER plus punctuation/capitalization and language failures. Dynamic/weight-only quantization and FP16 need no identical static calibration procedure but still need accuracy comparison. Small English publisher benchmarks cannot qualify Russian dictation.
5. **One NPU gate on a documented supported chip:** use the validated fixed graph, supported quantization and exact vendor compiler/runtime. Report which partitions execute on NPU and CPU. Qualify each SoC/driver combination independently; an AOT filename or successful compiler return is insufficient. Extend the matrix only after correctness and end-to-end improvement pass.

Static INT8 often needs representative activation ranges and backend-specific operator/quantization support. LiteRT GPU may use floating-point execution for quantized models; thus INT8 storage is not a promise of integer GPU arithmetic or lower peak RAM. Budget mapped weights, possible dequantized copies, compiled constants, activation arena, attention/KV/LSTM state, frontend/audio windows and temporary transfers. Full large-v3 FP32 source export is ~6 GB according to its publisher, before workspace memory. [LiteRT quantization](https://ai.google.dev/edge/litert/models/post_training_quantization), [GPU constraints](https://ai.google.dev/edge/litert/performance/gpu).

## Licensing, offline operation and delivery

GigaAM source/base weights and original OpenAI Whisper are MIT; retain notices and record modifications/conversion provenance. Check the exact source repository too: the Hugging Face `openai/whisper-large-v3` page currently labels its repository Apache-2.0, while the LiteRT conversion publisher labels its result MIT. Resolve and retain the applicable upstream/export notices in the artifact manifest rather than copying a family-wide license label. Parakeet TDT v3 is CC BY 4.0: retain attribution, license link and indication of conversion/quantization changes. LiteRT samples/source use Apache-2.0; ExecuTorch uses its repository license. Vendor compiler/runtime redistribution terms are separate from framework and model licensing. Keep Lacan's explicit separate model download with immutable revision, expected bytes/hash, atomic installation and offline reuse. A `.litertlm` bundle is an alternative packaging/orchestration layer, not necessary for raw `.tflite` CompiledModel. Supply tokenizer/frontend metadata with the graph. Bundle compatible runtime libraries or finish their explicit download before claiming first-launch offline support; Play-delivered model/runtime modules are unavailable before installation. On-device inference itself need not send audio to a service. Include native 16 KB page compatibility and coherent JNI/library packaging in the runtime gate.
